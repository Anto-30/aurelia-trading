- The repository ruleset named Execution (ID 24423833) was returned with enforcement=disabled; required_status_checks was empty; required_deployments was empty; and seven integration bypass actors had bypass_mode=always. Even when the ruleset is enabled, required check names and bypass policy need deliberate review. The connected integration returned HTTP 403 for classic branch-protection details, so those settings remain unverified, not presumed absent.
- Potentially critical workflow-boundary finding: .github/workflows/aurelia-assurance.yml triggers on all branch pushes and pull_request, selects the production environment, and contains steps that can pass DERIV authentication secrets to verification scripts when its prerequisite condition is true. Environment protection rules could not be queried through this connection. Before any credentials are provisioned, verify environment reviewer/branch restrictions and separate unprivileged PR CI from a protected, manually approved, verify-only broker workflow. Do not place secrets into an unprotected PR execution path.
- The main-branch config/LIVE_LOCK.yaml blob read during review still states live_trading_enabled=false, FINAL_EXECUTION_AUTHORIZATION=false, LIVE_EXECUTION=BLOCKED and capital_plane_mode=VERIFY_ONLY. This intake audit must not change that gate.
