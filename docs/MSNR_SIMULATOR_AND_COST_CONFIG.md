# MSNR frozen replay: strategy rules, costs, and execution semantics

## Scope

\`scripts/run_frozen_simulator.py\` is a research-only, candle-based replay for the registered \`MSNR_LIQUIDITY_SWEEP\` implementation in \`research/labs/deterministic_intraday_strategies.py\`. It reuses \`detect_msnr_liquidity_sweep\`; it is not a substitute generic moving-average strategy and does not create orders.

No complete runtime instrument/cost config is committed by default. The current strategy registry states that R_100 tick size, contract value/payoff, and instrument cost profile are not verified. The simulator therefore requires an explicit config and will refuse to infer these inputs from CSV decimal places or arbitrary defaults.

## Signal and execution

At each eligible candle close, \`calculate_signal(history=...)\` receives only the preceding closed candles; the candle used for entry is never passed to the signal function. The existing MSNR detector applies its reference lookback, low/high liquidity sweep, reclaim, local structure-break confirmation, deterministic regime filter, stop buffer, and opposing reference-range target. It rejects ambiguous two-sided sweeps. OHLC data does not provide DOM, footprint, delta, or actual traded volume, so volume-pop gating is blocked for the Deriv candle artifact.

The HMM regime label is generated by the existing causal \`RegimeDetector\`. At each refit, HMM parameters are fitted only to feature rows available before the signal candle. The current signal candle's feature is passed through forward filtering after the fit. Invalid or uncertain HMM states reject candidate entries; they are not relabelled as valid.

An accepted decision is timestamped against signal candle N-1; actual entry is scheduled for candle N's open. If the opening gap makes the stop/target geometry invalid, the ledger retains the original accepted signal and appends a separate cancellation event at candle N. This avoids rewriting an earlier signal using information from the future open. Only one position may be open at a time. No pyramiding or duplicate simultaneous trade is allowed.

Stop and target levels are checked against the entry/subsequent candle OHLC. If both levels are crossed in the same candle, the simulator assumes stop-first (pessimistic) ordering. If the open gaps through a stop, the raw exit reference is the worse open price; target fills do not assume price improvement. If neither stop nor target has hit by \`max_holding_bars\`, exit is at that candle close. Any still-open position at the end of available history is marked to the last candle close and labelled \`DATA_END_FORCED_CLOSE\`. This is a bar-based approximation; minute OHLC cannot establish the intrabar event sequence or exact fill timestamp.

## Required config

Create a JSON file using \`config/msnr_simulation.schema.json\` as the contract, and set its \`schema\` to \`aurelia.msnr_simulation_config.v1\`. All parameters must be explicit:
- Strategy: verified R_100 tick size, reference lookback, sweep threshold, stop buffer, reclaim window and allowed regimes.
- HMM: training-window length, refit cadence, feature window, filter type, confidence/entropy gates and deterministic random state.
- Execution: round-trip spread in underlying price units, incremental slippage per side, commission per size unit per round trip, cash conversion per price-unit/size-unit, position size and max holding period.
- Provenance: \`VERIFIED\` requires instrument and cost-source files plus exact SHA-256 digests and an observation timestamp. Use \`EXPLORATORY_UNVERIFIED\` only for an explicitly labelled scenario and pass \`--allow-unverified-scenario\`. Scenario output is not evidence of actual Deriv execution costs.

Cost calculation: spread is split equally across entry and exit; slippage is charged separately on each side. Entry/exit fill prices include their half-spread and slippage adjustments. Gross P&L is calculated from raw reference prices; spread, slippage and commission are separately deducted once from gross P&L. The initial-risk denominator uses the modeled entry fill-to-stop fill distance plus round-trip commission. Each record stores the reference prices, modeled fill prices, cost totals and entry/exit cost breakdown. The ledger verifies that those per-side costs reconcile to the totals.

The config SHA-256 binds all strategy/HMM/cost parameters into every ledger decision/trade. The data SHA-256 is sourced from the companion history manifest. The ledger refuses to overwrite existing output files and uses a chained per-record SHA-256, a final ledger SHA-256, and a companion manifest. Integrity hashes show post-capture byte consistency; they cannot prove decisions were not omitted before the logging call.

## Commands

The corrected historical artifact must exist first, including the manifest generated by \`scripts/fetch_deriv_history.py\`:
\`\`\`bash
python scripts/verify_deriv_history_manifest.py data/deriv/R_100_1m.csv

python scripts/run_frozen_simulator.py \\
  --data-path data/deriv/R_100_1m.csv \\
  --ledger evidence/trade_ledger.jsonl \\
  --config config/msnr_simulation.json

python -m research.atos_validation.audited_ledger evidence/trade_ledger.jsonl

python scripts/build_release_evidence.py \\
  --history-manifest data/deriv/R_100_1m.csv.manifest.json \\
  --data-path data/deriv/R_100_1m.csv \\
  --ledger evidence/trade_ledger.jsonl \\
  --evidence-dir evidence/
\`\`\`

For an explicitly hypothetical, unverified cost scenario only, add \`--allow-unverified-scenario\` to the simulator command. The configuration still has to state numeric values so assumptions are reproducible. Do not call scenario metrics verified execution economics, and do not use them to qualify a strategy.

The companion history manifest filename is \`R_100_1m.csv.manifest.json\`; it is not \`R_100_1m_manifest.json\`. The history verifier enforces exact uninterrupted coverage, which is stricter than a 99% coverage threshold. If the WSS capture fails, no simulator or evidence command should be run against a fabricated/substitute dataset.

## Safety

The simulator has no buy/sell, proposal, or account-authentication path. It is not connected to the canonical capital plane. Its outputs state \`LIVE_EXECUTION=BLOCKED\` and \`FINAL_EXECUTION_AUTHORIZATION=false\`. Do not edit \`config/LIVE_LOCK.yaml\` to make research tests pass.
